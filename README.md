# Databricks Lakeflow Designer — Customers, Orders & Sentiment Pipeline

A visual, no-code/low-code ETL pipeline built with **Databricks Lakeflow Designer** that ingests customer, order, shipment, and review data, enriches it, and produces analytics-ready Delta tables — including AI-powered sentiment analysis on customer reviews.

The entire pipeline is defined declaratively (each node's config lives in a YAML-style docstring) and exported as a runnable Databricks notebook: [`Visual data prep for Customers_Orders_Sentiment.designer.ipynb`](./Visual%20data%20prep%20for%20Customers_Orders_Sentiment.designer.ipynb).

## What this pipeline does

**Sources**
| Node | Type | Description |
|---|---|---|
| `Api_customers` | Python (API) | Loads `customers.csv` from a GitHub-hosted CSV via HTTP |
| `API_Shipments` | Python (API) | Loads `shipments.csv` from a GitHub-hosted CSV via HTTP |
| `orders` | Unity Catalog table | Reads `lakeflow_designer.raw.orders` |
| `order_items` | Unity Catalog table | Reads `lakeflow_designer.raw.order_items` |
| `Reviews` | Unity Catalog table | Reads `lakeflow_designer.raw.reviews` |

**Transformations**
- **Orders_join_Orderitems** — left joins `orders` with `order_items` on `order_id`.
- **Ordersitems_Join_Customer** — left joins the result with `customers` on `customer_id`.
- **OBT (One Big Table)** — left joins in `shipments` on `order_id` to produce a single denormalized order fact table.
- **Derive_order_month** — derives an `order_month` (`YYYY-MM`) column from `order_date`.
- **OrdersbyCity** — aggregates the OBT by `city`, computing total order count and total order value.
- **Count_OrderStatus_by_Month** — aggregates by `order_month` + `order_status` to count orders per status per month.
- **SentimentAnalysis** — runs Databricks' `ai_analyze_sentiment()` AI function on `review_body` to classify each review's sentiment, keeping all original review columns.
- **sorted** / **Sort_OrderStatus_by_Month_desc** — sort the aggregated results for reporting.

**Outputs (Delta tables in `lakeflow_designer.enrich`)**
| Table | Contents |
|---|---|
| `Sentiment` | Reviews enriched with an AI-generated sentiment label |
| `AggregatedOrders` | Total orders and total order value per city, sorted descending |
| `AggregatedOrderStatus` | Order counts by month and order status, sorted by most recent month |

## Pipeline flow

```
orders ─┐
        ├─ Orders_join_Orderitems ─┐
order_items ─┘                     │
                                    ├─ Ordersitems_Join_Customer ─┐
Api_customers (customers.csv) ─────┘                             │
                                                                  ├─ OBT ──┬─ OrdersbyCity ──────────────── sorted ─────────► AggregatedOrders
API_Shipments (shipments.csv) ───────────────────────────────────┘        │
                                                                          └─ Derive_order_month ─ Count_OrderStatus_by_Month ─ Sort_OrderStatus_by_Month_desc ─► AggregatedOrderStatus

Reviews ──► SentimentAnalysis (ai_analyze_sentiment) ─► Sentiment
```

## How it works

This notebook is generated by **Databricks Lakeflow Designer**, a drag-and-drop visual data-pipeline builder. Each cell corresponds to one node on the visual canvas:
- The docstring at the top of each cell holds the node's declarative configuration (id, template type, position on canvas, description, and settings).
- The generated Python/PySpark code beneath it is what Lakeflow Designer compiles from that configuration to actually execute the step (source reads, joins, aggregations, AI function calls, and Delta table writes).

Running the notebook end-to-end executes the whole pipeline: it reads raw data (from Unity Catalog tables and public CSVs), joins and enriches it, runs AI-based sentiment analysis on reviews, and writes three curated Delta tables for downstream analytics/BI.

## Tech stack

- **Databricks Lakeflow Designer** (visual pipeline authoring)
- **PySpark** / Delta Lake (execution and storage)
- **Unity Catalog** (`lakeflow_designer.raw.*` sources, `lakeflow_designer.enrich.*` outputs)
- **Databricks AI Functions** (`ai_analyze_sentiment`) for LLM-based sentiment classification

## Data

The [`data/`](./data) folder contains the raw sample CSVs used to seed this pipeline (loaded into the Unity Catalog `lakeflow_designer.raw` schema / served over HTTP for the pipeline's `Api_customers` and `API_Shipments` nodes):

| File | Key columns | Description |
|---|---|---|
| `customers.csv` | `customer_id`, `customer_name`, `email`, `phone`, `city`, `state`, `country`, `created_date` | Customer master data |
| `orders.csv` | `order_id`, `customer_id`, `order_date`, `order_status` | One row per order |
| `order_items.csv` | `order_item_id`, `order_id`, `product_id`, `quantity`, `unit_price`, `discount_pct`, `line_total` | Line items belonging to each order |
| `products.csv` | `product_id`, `product_name`, `category`, `subcategory`, `unit_price` | Product catalog |
| `reviews.csv` | `review_id`, `product_id`, `product_name`, `category`, `rating`, `review_title`, `review_body`, `reviewer` | Customer product reviews (input to the sentiment analysis step) |
| `shipments.csv` | `shipment_id`, `order_id`, `ship_date`, `ship_mode`, `shipping_cost` | Shipment details per order |
